# Playwrightによる実ゲーム計測

## 目的と起動方法

CDDA Playwright browser measurements Workflowは、指定されたGitHub Pages上のブラウザ版CDDAを7つの配布ファイルごとにダウンロードし、隔離したChromiumプロファイルで起動します。既存ユーザーのセーブ・MOD・設定は流用しません。既存の real_activity_fixture.py が試験専用の初期条件を作成し、実際の配布WebAssemblyを実行します。

Actionsから手動実行できます。base_urlは測定対象の配信先、scenarioは read4 / sleep / read / all、rendererは game / software / opengles2 / compare です。allは読書レベル4→5と睡眠を個別に実行し、compareは同じシナリオをsoftwareとopengles2で比較します。pushとpull_requestでも関連ファイルの変更時に計測します。

## 記録する内容

- 配布ファイル7点のSHA-256、サイズ、測定URL。
- 新規ゲーム開始ログまでの時間、ブラウザ例外、失敗リクエスト。
- Canvas内部解像度とCSS表示サイズ、拡大率、image-rendering、HTMLシェルのフォント読込状態。
- 移動キー長押し中のフレーム間隔p50/p95/p99/最大値、50/100/250ms超の停止回数、keydownから次フレームまでの時間。
- PerformanceObserverで観測したLong Taskの件数・総時間・最大時間。
- 可能な場合に、キー押下前後のクイックセーブからターン数と位置関連フィールドの差分。
- 読書・睡眠の実ゲーム観測結果、セーブスナップショット、Canvasスクリーンショット。
- Chromium関連プロセスのRSS/PSSを1秒間隔で採取した記録。
- Playwright trace、コンソールログ、構造化されたmeasurement.json。

成果物はActionsのartifact cdda-playwright-measurement-<run id>に30日間保存します。measurement.jsonが構造化データ、summary.mdが短い要約です。Canvas画像とPlaywright traceを併用して表示と停止箇所をレビューできます。

## 解釈上の制約

1. 測定対象はbase_urlから取得した配布物です。C++の差分はフルビルド・公開されていなければ計測対象に含まれません。PR上の計測も既定では現行のPages配布物を測ります。アセットSHAを記録して、測定対象の違いを取り違えないようにします。
2. GitHub ActionsのUbuntu runnerは4GB Chromebookの再現環境ではありません。相対比較やボトルネック探索には使えますが、実機の待ち時間・RAM・成功率を保証しません。
3. requestAnimationFrame間隔とLong Taskはブラウザ、ゲームのC++処理、描画、計測処理を含みます。純粋な1ターンCPU時間ではありません。ゲーム内ターン差分・[perf]ログと分けて評価します。
4. Chromium RSS合計は共有ページを重複計上し得ます。PSSも読み取れたChromium関連プロセスだけの合計で、OS全体のピークRAMではありません。
5. キー押下から次フレームまでの時間は入力応答の代理指標です。保存前後の差分が取れない場合、入力イベント数だけを根拠に「移動した」と判断しません。
6. 自動OCRや文字列の正誤判定は行いません。日本語の崩れはスクリーンショットを目視し、文字列破損・欠字・字幅・輪郭に分類します。HTMLのTerminusフォント確認はゲーム内タイルの字形保証ではありません。
7. read4は60秒の観測であり、レベル5到達を強制しません。敵発見などの確認画面が出た場合、停止画面とログを証拠として扱い、待たされた時間をターン処理時間へ読み替えません。
8. 計測値だけで最適化をマージしません。ゲーム状態、乱数、AI／危険検知の頻度、保存と再ロードの回帰を別途確認します。

## 各症状のレビュー手順

### 文字が崩れて見える

Canvasの実サイズ、CSS表示サイズ、拡大率、image-rendering、選択中の描画方式を確認し、添付画像を比較します。文字列自体が化けている場合は翻訳・UTF-8・描画前の文字列を調べ、空白や四角になる場合はフォントの字形収録とタイルセットを調べます。輪郭や幅だけが不自然なら拡大率・補間を比較します。CSSフォントだけを変更してゲーム内テキストも直ったと判断しません。

### 移動キーの連打・長押し

入力イベント数と、同じ時間帯のフレーム停止・Long Taskを照合します。キーイベントが届かない場合はSDLキューとrepeat抑制、イベントが届いても画面が止まる場合はターン処理・描画のどちらが支配的か調べます。ターン・位置の保存差分が取れたときだけ実移動量の証拠にします。

### セーブと長時間活動

読書・睡眠の実ゲーム観測、ターン差分、保存された活動状態、描画停止、Long Task、Chromiumメモリを別々に見ます。ゲーム内部のファイル直列化とIndexedDBへの永続化は違う段階です。保存高速化のために保存を間引いたり、ターン・AI・乱数消費を省略したりしません。

## 再現性

各実行のJSONに日時、URL、ブラウザ、シナリオ、描画方式、配布ファイルのハッシュを残します。改善前後は同じ配布物、初期条件、シナリオ、描画方式で比較し、Pagesのビルドが切り替わったら新しい測定対象として扱ってください。
