# Playwrightによる実ゲーム計測

## 目的と起動方法

CDDA Playwright browser measurements Workflowは、指定されたGitHub Pages上のブラウザ版CDDAを7つの配布ファイルごとにダウンロードし、隔離したChromiumプロファイルで起動します。既存ユーザーのセーブ・MOD・設定は流用しません。既存の real_activity_fixture.py が試験専用の初期条件を作成し、実際の配布WebAssemblyを実行します。

Actionsから手動実行できます。base_urlは測定対象の配信先、scenarioは read4 / sleep / read / all、rendererは game / software / opengles2 / compare です。allは読書レベル4→5と睡眠を個別に実行し、compareは同じシナリオをsoftwareとopengles2で比較します。populationは0 / 32 / 64 / 128 / 200体の対照条件で、0以外はsleepシナリオのみ許可します。これはデバッグ透明化を同一条件で付けた制御ストレス試験で、敵対行動を通常プレイそのままに再現する試験ではありません。読書の進行や中断条件を混ぜずに、個体数増加時のメモリ・長時間タスク・入力応答を比較する目的です。pushとpull_requestでも関連ファイルの変更時に配信版を計測します。また、Build CDDA 0.I WebAssembly Workflowがmainで成功終了すると、同じrunに保存された cdda-0I-web-bundle 成果物を直接ダウンロードして測定します。これによりPagesへの反映待ちやキャッシュと切り離して、フルビルド直後のソース成果物を測定できます。ビルド失敗時は計測を開始しません。

## 記録する内容

- 配布ファイル7点のSHA-256、サイズ、測定URL。
- 新規ゲーム開始ログまでの時間、ブラウザ例外、失敗リクエスト。
- Canvas内部解像度とCSS表示サイズ、拡大率、image-rendering、HTMLシェルのフォント読込状態。Playwrightのコンポジタから取得した同一の静止Canvas画像を75%サイズで表示し、`image-rendering: pixelated` と `auto` で比較画像を作る。これにより同じゲーム画面を使ってブラウザ側の拡大補間の影響を比較する。
- 移動キー長押し中のrequestAnimationFrameコールバック間隔p50/p95/p99/最大値、50/100/250ms超の間隔数、keydownから次コールバックまでの時間。計測区間の前に始まった長い間隔を混ぜないよう、時刻で区間を切り出す。
- PerformanceObserverで観測したLong Taskの件数・総時間・最大時間。
- 可能な場合に、キー押下前後のクイックセーブからターン数と位置関連フィールドの差分。
- F5押下時刻から仮想ファイル更新、`FS.syncfs`開始・終了までを同一の `performance.now()` 時刻軸で記録し、保存中のRAF間隔・Long Task・同期結果も採取。ゲーム内部のファイル更新とIndexedDBへの永続化を区別する。
- キーを離した直後に保存し、さらに500ms静置して再度保存。後段の保存でターン差分が増えていないか調べ、離上後の残留入力を検出する。
- 読書／睡眠シナリオの保存データから、`[perf]`ログ、活動終了メッセージ、睡眠関連効果を抽出する。観測窓の時間と、ゲーム内ログの実処理時間は別々に扱う。
- 読書・睡眠の実ゲーム観測結果、セーブスナップショット、Canvasスクリーンショット。
- Chromium関連プロセスのRSS/PSSを1秒間隔で採取した記録。
- Playwright trace、コンソールログ、構造化されたmeasurement.json。

成果物はActionsのartifact cdda-playwright-measurement-<run id>-attempt-<attempt>に30日間保存します。同じrunの再実行でも成果物が衝突しないようにattempt番号を含めます。measurement.jsonが構造化データ、summary.mdが短い要約です。Canvas画像とPlaywright traceを併用して表示と停止箇所をレビューできます。`measurement-source.json` には、公開URL計測か特定ビルド成果物か、ビルド実行ID・再実行番号、コミットSHA、計測ハーネスのSHA、公開版では7つの主要配布ファイル、ビルドartifactでは追加のネストされたファイルも含めたハッシュを記録します。新しいビルドは別の `cdda-build-provenance` artifactに Emscripten版、Asyncify/JSPI、リンク最適化、SIMD設定を記録します。過去ビルドに構成情報がない場合は、出所のSHAは確認できても設定同定は未確認として残します。

計測終了時には、起動・セーブ・描画・入力の記録だけでなく、fixtureの期待状態も検査します。`read4` は保存されたスキルレベル5到達と読書終了、`sleep` は14,400ターン経過と覚醒メッセージ、両者ともキャラクター保存とゲーム活動の終了を要求します。予期しないリクエスト失敗もCI失敗とし、実測で確認された `cataclysm-tiles.data` の `net::ERR_ABORTED` だけを限定的に許容して記録します。さらに、最初の計測タブを閉じてプロフィールの排他ロックを解放した後、同じブラウザコンテキスト内の新しいページで同じプロフィールを再度開き、IndexedDB/IDBFSからワールド名・キャラクターセーブ名・ターン・活動・座標・移動値が一致することを検証します。復元できない、または値が違う場合は計測を失敗にします。この追加タブの初期化はChromiumメモリ採取区間にも含まれるため、メモリピークはゲーム中だけのピークではなく、再読み込み検証時のピークも含みます。これらは回帰検出を強化するもので、実機のストレージ消去・ブラウザ終了後の復元耐久性まで保証するものではありません。`text-scale-pixelated.png` と `text-scale-auto.png` は同じ静止Canvas画像をCSSで75%に縮小した比較画像です。CanvasのWebGL描画状態によって `canvas.toDataURL()` が真っ黒になることがあるため、画面キャプチャはPlaywrightのコンポジタ経由で採取します。

## 解釈上の制約

1. 測定対象はbase_urlから取得した配布物です。C++の差分はフルビルド・公開されていなければ計測対象に含まれません。PR上の計測も既定では現行のPages配布物を測ります。アセットSHAを記録して、測定対象の違いを取り違えないようにします。
2. GitHub ActionsのUbuntu runnerは4GB Chromebookの再現環境ではありません。現在のPlaywright起動設定ではChromiumがSwiftShader経由のソフトウェアWebGLフォールバックを使用するため、ハードウェアGPUの実機とは描画条件が異なります。相対比較やボトルネック探索には使えますが、実機の待ち時間・RAM・成功率を保証しません。
3. requestAnimationFrame間隔とLong Taskはブラウザ、ゲームのC++処理、描画、計測処理を含みます。RAFの呼び出し間隔は描画FPSそのものではなく、アイドル待ちや確認ダイアログでも長くなるため、実際の画面・ターン差分・[perf]ログと合わせて評価します。純粋な1ターンCPU時間とは区別します。
4. Chromium RSS合計は共有ページを重複計上し得ます。PSSも読み取れたChromium関連プロセスだけの合計で、OS全体のピークRAMではありません。
5. キー押下から次フレームまでの時間は入力応答の代理指標です。保存前後の差分が取れない場合、入力イベント数だけを根拠に「移動した」と判断しません。
6. 自動OCRや文字列の正誤判定は行いません。日本語の崩れはスクリーンショットを目視し、文字列破損・欠字・字幅・輪郭に分類します。HTMLのTerminusフォント確認はゲーム内タイルの字形保証ではありません。
7. read4は60秒の観測です。計測の成功条件として、保存データでレベル5到達と読書終了を要求します。敵発見などの確認画面で進行が阻まれて条件を満たせなかった場合、その実行は成功扱いにせず、スクリーンショットとログを失敗原因の証拠として扱います。perfログの時間にはモーダル待ちが混入し得るため、純粋なターン処理時間として扱いません。
8. 計測値だけで最適化をマージしません。ゲーム状態、乱数、AI／危険検知の頻度、保存と再ロードの回帰を別途確認します。

## 各症状のレビュー手順

### 文字が崩れて見える

Canvasの実サイズ、CSS表示サイズ、拡大率、image-rendering、選択中の描画方式を確認し、添付画像を比較します。文字列自体が化けている場合は翻訳・UTF-8・描画前の文字列を調べ、空白や四角になる場合はフォントの字形収録とタイルセットを調べます。輪郭や幅だけが不自然なら拡大率・補間を比較します。CSSフォントだけを変更してゲーム内テキストも直ったと判断しません。

### 移動キーの連打・長押し

入力イベント数と、同じ時間帯のフレーム停止・Long Taskを照合します。キーイベントが届かない場合はSDLキューとrepeat抑制、イベントが届いても画面が止まる場合はターン処理・描画のどちらが支配的か調べます。ターン・位置の保存差分が取れたときだけ実移動量の証拠にします。

### セーブと長時間活動

読書・睡眠の実ゲーム観測、ターン差分、保存された活動状態、描画停止、Long Task、Chromiumメモリを別々に見ます。F5前に既存の保存処理が終わるまで待ってから入力を計測し、F5後に保存ファイルの変化が検出されなかった場合は遅延の実測値ではなく「期限内に更新を確認できず」として扱います。ゲーム内部のファイル直列化とIndexedDBへの永続化は違う段階です。保存高速化のために保存を間引いたり、ターン・AI・乱数消費を省略したりしません。

## 再現性

各実行のJSONに日時、URL、ブラウザ、シナリオ、描画方式、配布ファイルのハッシュを残します。測定値と所見は [実測レビュー（2026-10-27）](./REVIEW-2026-10-27.md) に整理しています。改善前後は同じ配布物、初期条件、シナリオ、描画方式で比較し、Pagesのビルドが切り替わったら新しい測定対象として扱ってください。
